# Участие в разработке

## Предложить изменение

Создайте Issue с номером правила, описанием проблемы, предложенным текстом и примером. Создайте ветку от `main` (например, `docs/accessibility-improvement`).

## Коммиты

Применяйте Conventional Commits: `docs: clarify lesson steps`, `fix: correct link`, `ci: update checks`, `chore: update dependencies`. Одна логическая правка — один коммит.

## Проверка и ревью

Перед PR запустите линтер и строгую сборку, проверьте ссылки и читаемость. В описании PR укажите цель, изменённые страницы и результаты проверок. Попросите коллегу оставить минимум три содержательных замечания. Ответьте на каждое и внесите правки отдельным коммитом. Слияние в `main` — после одобрения и успешного CI.

## Локальная сборка

```bash
python -m venv .venv
python -m pip install -r requirements.txt
python -m mkdocs serve
python -m mkdocs build --strict
```

## Новый раздел

Добавьте Markdown-файл в `docs/`, задайте уникальные идентификаторы правил, добавьте файл в `nav` в `mkdocs.yml`, проверьте внутренние ссылки и откройте PR.
