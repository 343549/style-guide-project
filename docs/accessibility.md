# Доступность текста

**Д01.** Используйте короткие абзацы и понятные слова; не полагайтесь на цвет как единственный признак.

**Д02.** Соблюдайте логическую иерархию заголовков без пропуска уровней.

**Д03.** Делайте текст ссылок самодостаточным и понятным вне контекста.

**Д04.** Для смысловых изображений пишите альтернативное описание; для декоративных допускается пустое.

**Д05.** Не заменяйте текстовую инструкцию скриншотом.

**Д06.** Сообщение об ошибке должно содержать следующий шаг для пользователя.

**Д07.** Код должен оставаться текстом; таблицы должны иметь заголовки столбцов.

**Д08.** Проверяйте чтение с клавиатуры, масштаб 200% и узкий экран шириной 320 CSS-пикселей.

## Дополнительные правила доступности

### Д09. Используйте понятные сообщения об ошибках

Сообщение должно объяснять, что произошло и какое действие необходимо выполнить пользователю. Не используйте технические коды ошибок без пояснений.

**Пример:** вместо «Ошибка 403» напишите «У вас нет доступа к этому уроку. Проверьте права доступа или обратитесь к преподавателю».

### Д10. Обеспечивайте понятную навигацию

Названия разделов должны точно отражать их содержание. Используйте одинаковые названия для одних и тех же функций во всех документах.

**Пример:** используйте название «Мои курсы» во всех инструкциях вместо чередования «Мои курсы», «Обучение» и «Список занятий».

### Д11. Не передавайте информацию только цветом

Важные состояния и предупреждения обозначайте текстом. Пользователь должен понимать сообщение даже при отсутствии цветового восприятия.

**Пример:** вместо «Красные поля заполнены неверно» напишите «Поля с пометкой „Ошибка“ необходимо исправить».

### Д12. Используйте понятные подписи к таблицам

Каждая таблица должна иметь заголовки столбцов и краткое пояснение назначения. Не используйте таблицы только для визуального расположения текста.

**Пример:** таблица «Результаты обучения» содержит столбцы «Курс», «Прогресс» и «Дата завершения».
