# Инструкция

Инструкция помогает пользователю самостоятельно выполнить конкретную задачу и
получить проверяемый результат. Она описывает путь от исходного состояния до
результата, а не просто перечисляет возможности продукта.

## Когда нужна инструкция

Создавайте инструкцию, если пользователю необходимо выполнить
последовательность действий: начать урок, записаться на курс, отправить задание
или восстановить доступ.

Не используйте формат инструкции для общего описания функции. Если действий
нет, подготовьте справочную страницу. Если нужно объяснить понятие, используйте
учебный материал с определением и примерами.

## Подготовка

Перед написанием инструкции определите:

- задачу пользователя;
- целевую аудиторию и её уровень знаний;
- начальное состояние системы;
- необходимые права, данные и программы;
- конечный результат;
- возможные ошибки и способы их устранения;
- версию интерфейса, на которой проверялись шаги.

Выполните описываемую задачу самостоятельно. Не составляйте шаги только по
памяти или скриншотам старой версии.

## Название

Название должно обозначать результат или задачу пользователя. Используйте
глагол действия и название объекта.

**Подходящие названия:**

- «Как начать урок»;
- «Как отправить решение задания»;
- «Как восстановить доступ к курсу».

**Неподходящие названия:**

- «Работа с уроками» — результат не определён;
- «Инструкция пользователя» — задача не названа;
- «Полезная информация» — содержание невозможно предсказать.

## Обязательные разделы

### Для кого

Укажите роль и ситуацию читателя. Не используйте формулировку «для всех
пользователей», если отдельным ролям доступны разные функции.

**Пример:** «Инструкция предназначена для учащегося, который впервые открывает
урок назначенного курса».

### Цель

Опишите один результат, который пользователь получит после выполнения шагов.
Результат должен быть проверяемым.

**Вместо:** «Познакомиться с платформой».

**Пишите:** «Открыть первый урок курса и перейти к учебному материалу».

### Предварительные условия

Перечислите только те условия, без которых шаги нельзя выполнить. Укажите
необходимые права, активную учётную запись, завершённые действия и исходные
данные. Если подготовка требует отдельной длинной процедуры, дайте ссылку на
другую инструкцию.

### Шаги

Используйте нумерованный список. Каждый шаг должен содержать одно действие и,
если необходимо, короткое пояснение результата этого действия.

Начинайте шаг с глагола: «Откройте», «Выберите», «Введите», «Нажмите» или
«Проверьте». Называйте элементы интерфейса дословно и заключайте их названия в
кавычки.

**Вместо:** «Откройте курс и выберите урок, а затем нажмите кнопку запуска».

**Пишите:**

1. Откройте курс «Основы Python».
2. Выберите урок «Переменные».
3. Нажмите «Начать урок».

Не объединяйте в одном шаге действия, которые могут завершиться разными
ошибками. Не описывайте очевидные движения мыши и не используйте направления
«слева» или «справа», если расположение элемента может измениться на мобильном
экране.

### Ожидаемый результат

После шагов объясните, что пользователь увидит и как убедится в успешном
завершении задачи.

**Пример:** «Откроется страница урока. В верхней части страницы отображается
название „Переменные“, а кнопка „Начать урок“ заменяется кнопкой „Продолжить“».

Не используйте только формулировку «Готово». Она не позволяет проверить
результат.

### Решение проблем

Опишите вероятные проблемы, которые пользователь может распознать. Для каждой
проблемы укажите:

1. наблюдаемый признак;
2. проверяемую причину;
3. действие пользователя;
4. ожидаемый результат после исправления;
5. способ обратиться за помощью, если проблема сохраняется.

Не показывайте технический код без объяснения. Не просите отправлять пароль,
токен или другие секретные данные.

## Скриншоты

Скриншот дополняет текст, но не заменяет шаг. Добавляйте изображение только
тогда, когда оно помогает найти сложный элемент или сравнить состояние
интерфейса.

Для каждого смыслового изображения:

- добавьте альтернативное описание;
- выделите только область, относящуюся к шагу;
- скройте персональные данные;
- укажите номер или подпись, если на изображение ссылается текст;
- обновите изображение после изменения интерфейса.

## Полный пример структуры

```markdown
# Как начать урок

**Для кого:** для учащегося, который впервые открывает назначенный курс.

**Цель:** открыть первый урок и перейти к учебному материалу.

## Предварительные условия

- Пользователь вошёл в учебную учётную запись.
- Курс «Основы Python» добавлен в раздел «Мои курсы».

## Порядок действий

1. Откройте раздел «Мои курсы».
2. Выберите курс «Основы Python».
3. Откройте урок «Переменные».
4. Нажмите «Начать урок».

## Результат

Откроется учебный материал урока «Переменные».

## Если урок недоступен

Проверьте, завершены ли обязательные предыдущие уроки. Если проблема
сохраняется, обратитесь к администратору курса и сообщите название курса.
Не отправляйте пароль.
```

Готовый вариант доступен на странице
[«Как начать урок»](examples/start-lesson.md).

## Проверка перед публикацией

Убедитесь, что:

- название обозначает конкретную задачу;
- аудитория, цель и предварительные условия указаны до шагов;
- один шаг содержит одно действие;
- названия элементов совпадают с интерфейсом;
- последовательность выполнена в тестовом окружении;
- после шагов указан проверяемый результат;
- типичные проблемы имеют конкретные решения;
- изображения не заменяют текст;
- инструкция не содержит секретных или персональных данных;
- другой участник воспроизвёл инструкцию во время ревью.
