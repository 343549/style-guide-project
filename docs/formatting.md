# Структура и оформление

## Заголовки

### О01. Соблюдайте последовательную иерархию

У документа должен быть один заголовок первого уровня. После него используйте
заголовки второго уровня, а внутри них — третьего. Не пропускайте уровни:
иерархия помогает читателю и программам экранного доступа понять структуру.

Для обычной страницы LearnPath используйте не более трёх уровней: `#` для
названия страницы, `##` для основных разделов и `###` для подразделов. Если
требуется четвёртый уровень, пересмотрите структуру: разделите длинную страницу
или замените мелкие подразделы списком. После `##` нельзя сразу ставить `####`.

**Ожидаемый результат:** по списку заголовков можно понять содержание и
последовательность страницы, не читая основной текст.

**Пример:**

```markdown
# Начало работы

## Предварительные условия

## Открытие курса

### Если курс недоступен
```

## Структура инструкции

### О02. Дайте контекст перед шагами

В начале инструкции укажите цель, аудиторию и предварительные условия. Читатель
должен заранее понимать, подходит ли ему инструкция и что необходимо
подготовить.

### О03. Описывайте одно действие в одном шаге

Каждый пронумерованный шаг должен содержать одно проверяемое действие. После
последнего шага опишите ожидаемый результат. Если результат не наступил,
добавьте раздел с диагностикой проблемы.

## Списки и ссылки

### О04. Выбирайте список по смыслу

Нумерованный список показывает обязательную последовательность действий.
Маркированный список подходит для вариантов или независимых условий. Не
используйте нумерацию только ради визуального оформления.

### О05. Называйте назначение ссылки

Текст ссылки должен сохранять смысл вне окружающего предложения. Формулировка
«Откройте каталог курсов» понятнее, чем «Нажмите здесь», и помогает при
навигации со списком ссылок.

## Таблицы, изображения и код

### О06. Сопровождайте визуальные элементы текстом

В таблицах указывайте заголовки столбцов и единицы измерения. Для смысловых
изображений добавляйте альтернативное описание, передающее цель изображения,
а не перечисление всех деталей.

### О07. Делайте примеры кода проверяемыми

Оформляйте код ограждёнными блоками с указанием языка. Приводите полную команду,
условия запуска и ожидаемый результат. Не включайте в пример пароли, токены и
другие секреты.
